# Contributing

Terms are explained in the [glossary](docs/GLOSSARY.md).

Start from PROJECT.md and research/PROTOCOL.md. Propose one measurable change,
its expected behavior and the comparison that can establish its effect.

Use C++17, small interfaces, behavioral TDD and portable CMake targets. Record
red/green evidence for new behavior and run the affected CTest labels. Profile
before performance tuning and report the workload and execution conditions.

Attribute reused code, datasets and methods with exact upstream revisions and
license notices. Keep public development examples synthetic and place hidden
evaluation data and credentials in protected external storage.

Results include configuration, expected case count, failures, source evidence,
timings, token accounting and uncertainty. Distinguish component checks, adapted
experiments and historical reproductions in reports.
