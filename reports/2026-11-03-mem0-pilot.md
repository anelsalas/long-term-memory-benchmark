# Mem0 pilot: one LongMemEval question

November 3, 2026. This adapted pilot evaluates one published multi-session
question, `bb7c3b45`, against the previously recorded dense-retrieval baseline.
Both used GPT-6.1-sol/high as reader and judge and a 6,000 estimated-token content
budget. Each judgment is a model judgment; a single question cannot establish a
system-wide accuracy rate.

| Measure | Mem0 3.3.1 | Existing dense baseline |
|---|---:|---:|
| GPT judge's answer verdict | Correct | Correct |
| Reader input / output tokens | 17,363 / 16 | 10,894 / 13 |
| Reader time | 5.68 s | 3.42 s |
| Retrieval preparation | 689 ms | 30 ms |

Mem0's preparation includes local question embedding and search. The dense
baseline used cached embeddings, including the question vector. These one-off
timings describe different preparation paths and are not a controlled latency
comparison. Both methods used a 6,000-token estimate for selected content, while
their JSON framing and selected material differed. Mem0 sent 91 memory records
to the reader; the estimate does not include all surrounding JSON and model
instructions. The two reader token counts include the reported model input.

## Ingestion

The 47-session history produced 541 Mem0 memory events using 47 GPT-6.1-sol/low
calls. Reported ingestion usage was 741,357 input and 37,277 output tokens.
Summed observed session client time was 46 minutes 38 seconds, excluding gaps;
this is a one-time ingestion measurement for this case. One session produced no
memory events. All calls reported usage; the actual monetary cost was not
measured. The reader and judge required one additional GPT call each, with the
judge reporting 5,444 input and 5 output tokens.

Selected memories referenced every labelled evidence **session**. This is
session-level provenance, not proof that every labelled turn was recovered.
Mem0 3.3.1 uses additive extraction and a search combining semantic, keyword and
entity-related signals; it is a versioned adaptation of the paper's earlier
architecture. Extraction used the local SQLite-backed store and local
Qwen3-Embedding-0.6B service. Dates were supplied in metadata and input text.

During part of ingestion, five-second sampling observed a peak working set of
approximately 1.02 GiB for the embedding process and 346 MiB for the Mem0
sidecar. Sampling began after ingestion started and excludes model subprocesses
and remote inference; these are sampled process peaks, not whole-machine peaks.

The ten selected multi-session questions contain 490 sessions in total. If each
session required one extraction call as in this case, plus one reader and one
judge call per question, the estimate would be about 510 calls; actual calls and
token use can vary. The measured input tokens extrapolate to about 7.4 million
for ten similarly sized cases, plus answering and judging. This estimate is based
on one case and is not a price quote.

The [dialogue-free data](2026-11-03-mem0-pilot.json) records measured usage,
timings, resource sampling, and prompt fingerprints. The matched existing results
are described in the [reader comparison](2026-11-02-reader-comparison.md).
