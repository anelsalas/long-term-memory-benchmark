# Project instructions

Terms are explained in the [glossary](docs/GLOSSARY.md).

Build a C++17 benchmark for reliable long-term memory access. Target
native Windows ARM64 and use CMake/CTest, behavioral unit tests and TDD.
Read README.md, PROJECT.md, STATUS.md, DECISIONS.md and the latest handoff before
changes. Keep objectives and documentation concise, affirmative and specific.

Publish original source, public synthetic development fixtures, citations and
reviewed results. Store credentials, private histories and hidden evaluation
answers outside the repository. Preserve upstream attribution and licenses.
Record actual tests and distinguish offline component checks from model results.

Workers own assigned files exclusively and report evidence in reports/. The
coordinator owns root documentation, review, integration, commits and publication.
Use bounded work; model calls and rented compute require a declared budget.
